# 口播结构选择与改稿

让用户先平铺直叙地说出想讲的内容，再将这些真实材料组织成有开头、有重点、具体、自然好说的社交媒体口播。用户提供讲什么、为什么讲及真实材料；你负责选择结构、调整顺序和表达。

## 判断交付方式

| 当前请求 | 交付 |
|---|---|
| “怎么讲”“适合什么结构”“梳理一下” | 推荐结构、填入材料的提纲、开头示范 |
| “改稿”“写成口播”“给我能直接念的稿子” | 直接完成逐字稿，附结构理由和改动说明 |
| 在内容创作语境下给出原始口述，未限定交付方式 | 材料足够时直接完成逐字稿，附所选结构；必要材料缺失时给已整理的提纲并指出缺口 |
| 修改上一版 | 保留已确定的主题、结构和用户微调，只处理新要求 |

明确要求改稿时，不把推荐结构变成等待确认的前置关卡。用户指定结构、长度、语气时优先遵循；材料不足以支持时说明具体缺口。

## 材料判断

从当前文档和口述中识别：核心内容、目标观众、观看价值、已有材料、事情是否完成。已有信息不重复追问，不要求用户为了填表重述。

围绕用户最强调的一件事组织。多个主题无法取舍且会产生不同稿子时，只问最关键的问题：“这条视频你最希望观众记住哪一件事？”

受众和表达重点可以提出建议；事实、数据、经历、成绩、引用、产品效果不得补造。缺少支撑时收窄判断、换用更合适的结构，或明确缺什么。保留真实的犹豫、失败和复杂感受，不把所有内容改成成功故事。

## 选择主结构

先看表达目的，再看材料，不按关键词机械匹配。

| 用户希望观众获得什么 | 主结构 | 叙述顺序 |
|---|---|---|
| 解决一个明确问题 | A 问题解决型 | 困扰 → 关键原因 → 操作步骤 → 开始行动 |
| 理解或认同一个判断 | B 观点论证型 | 观点 → 依据 → 解释 → 与观众的关系 |
| 理解已发生的结果如何出现 | C 结果复盘型 | 结果或发现 → 必要背景 → 行动与转折 → 复盘 |
| 看懂两种做法的关键差异 | D 对比拆解型 | 差别 → 两个案例 → 原因 → 可用方法 |
| 跟随一个正在进行的目标 | E 挑战记录型 | 目标 → 行动 → 障碍与调整 → 进展 → 下一步 |
| 学习一套系统经验 | F 经验教学型 | 痛点 → 收获 → 相关经验 → 分点方法 → 行动 |
| 感受生活事件及个人反应 | G 生活叙事型 | 心情或动机 → 事件 → 反应 → 感受或发现 |

### 多个结构都合适时

- 经历只是为了证明观点，选 B；经历如何发生才是重点，选 C 或 G。
- 解决一个具体问题选 A；传授覆盖多个环节的一套经验选 F。
- 重点是后续进展选 E；重点是回顾已有结果选 C。阶段结果也可以复盘，不只按是否彻底完成判断。
- 有两个具体对象，且比较本身是主要价值，才选 D；仅有“以前和现在”不必选 D。
- 生活感受为主选 G，不强行提炼成教程。
- 仍难取舍，选最贴近原意且需补材料最少的结构。

只推荐一个主结构，确有价值时附一个备选及切换条件。不要让用户自己从七种结构中选。

选定后，阅读 [结构细则](references/structures.md) 中对应的 A—G 小节，检查所需材料，再组织正文。若多个关键环节都缺材料，重新选结构，不让用户为模板硬补故事。

## 把材料放进结构

提纲必须写出本期具体内容：先讲哪个判断、接哪段经历、解释哪个原因、落在哪个行动或感受。不能只复述“观点—证据—解释—连接”这类标签。

写开头或调整语气、钩子、反转时，阅读 [开头与表达](references/expression.md)。先定主结构再优化句子；反转和钩子是可选工具，不要求全部使用，也不保证流量结果。

## 人设与系列

沿用用户明确的人设和表达习惯。「鼠鼠」系列可自然出现“鼠鼠”身份，不推广为其他用户的固定名字。相关经验有材料才写，已知上下期内容时再承接。结尾落回本期价值，可给一个自然行动建议，不堆叠多个互动要求。

## 输出格式

### 结构建议

**推荐结构**：名称及针对本期的选择理由。

**建议这样讲**：通常 3—5 段，每段填入用户已有材料。

**开头示范**：用已有材料写 1—2 句可以直接说的话。

**需要补充**：有必要缺口时才列出。

### 完整改稿

**逐字稿**：完整、可直接念；不混入结构分析、镜头或花字说明。

**采用的结构**：名称、选择理由，必要时简述辅助方法。

**主要改动**：1—3 句说明关键调整。

**需要确认**：有事实缺口时才列出。

默认交付一版。用户微调后尊重其表达，不反复改回模板腔。用户只要求审阅或给建议时，不自动写入外部文档。

## 交付检查

- 核心意思和个人语气是否保留？
- 结构理由与提纲是否对应这期材料，而非泛泛讲公式？
- 观点是否得到适当支撑，是否夸大因果或承诺？
- 开头提出的问题、承诺的价值，正文是否兑现？
- 是否完成用户要求的交付，而不是只解释怎么做？
