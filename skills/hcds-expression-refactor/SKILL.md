# HCDS Expression Refactor · 表达重构

用户先用一句话说明想讲什么，再平铺直叙地口述过程；你负责清理噪音、整理主题、选择叙事结构，基于用户提供的材料直接改稿，产出有个人语气、能直接念的完整口播稿。已有口述可以直接处理，不要求用户重新按格式输入。用户看稿后重新说一遍是其个人用法，不是必须执行的第二轮流程。

## 判断交付方式

在内容创作场景中，调用本 Skill 并提供待处理口述时，默认直接完成改稿，包括“怎么讲”“梳理一下”等未明确限定交付的请求。不先停在结构选择或提纲，不要求确认结构后才能继续。

只有用户明确只要建议、讨论结构、提纲、审阅或不写全文时，才按该限定交付。修改上一版时保留已确定的主题、结构和用户微调，只处理新要求。用户指定主题、篇数、结构、长度、语气时优先遵循；材料不足以支持时简短指出具体缺口，不编造补齐。

## 清理口述，保留个人表达

- 删除无意义的“嗯、啊、这个、那个”等口头填充、卡壳、自我打断和没有新增信息的重复解释。
- 合并绕来绕去才讲清楚的内容，让句子和段落更紧凑。
- 保留有内容的个人观点、当时的心境、看到人或事后的反应、态度和习惯用词。
- 按词句在上下文中的作用处理，不使用机械禁词表。“我觉得”“其实”“这个”等有真实表达作用时保留；有意强调的重复不等于口水话。
- 整理后仍是自然口语，不改成书面报告、营销套话或统一的人设腔。这些是编辑判断，不是机械替换规则。

## 材料判断与主题拆分

从当前文档和口述中识别：核心内容、目标观众、观看价值、已有材料、事情是否完成。已有信息不重复追问，不增加必填问卷。

每篇各自讲清一个核心主题，按材料判断是否拆篇：

- 两个主题能够独立讲清、各自有观看价值且材料足够时，可以直接拆成两篇，各自选择结构并写完整稿。
- 同一故事里的主线、对照、动机或解释，不机械拆成不同稿件；一个主结构可以容纳同一故事的多条线索。
- 不因为输入长就拆篇，不默认必须拆两篇，也不为了只交一篇而删除另一段完整且有价值的内容。
- 有价值但不足以独立成稿的支线，简短放到稿外的“其他可用素材”；没有则不输出这一栏，不编造材料扩写成第二篇。
- 用户明确只要一篇或指定主题时优先遵从，其余有独立价值的素材可在稿外简短保留。

一次交付多个主题的稿件，不等于给同一主题生成多个备选版本；不默认生成同一主题的多版稿。

受众和表达重点可以提出建议；事实、数据、经历、成绩、引用、产品效果不得补造。缺少支撑时收窄判断、换用更合适的结构，或明确缺什么。保留真实的犹豫、失败和复杂感受，不把所有内容改成成功故事，不夸大因果、不强行升华、不承诺流量。

## 选择主结构

先看表达目的，再看材料，不按关键词机械匹配。

| 用户希望观众获得什么 | 主结构 | 叙述顺序 |
|---|---|---|
| 解决一个明确问题 | A 问题解决型 | 困扰 → 关键原因 → 操作步骤 → 开始行动 |
| 理解或认同一个判断 | B 观点论证型 | 观点 → 依据 → 解释 → 与观众的关系 |
| 理解已发生的结果如何出现 | C 结果复盘型 | 结果或发现 → 必要背景 → 行动与转折 → 复盘 |
| 看懂两种做法的关键差异 | D 对比拆解型 | 差别 → 两个案例 → 原因 → 可用方法 |
| 跟随一个正在进行的目标 | E 挑战记录型 | 目标 → 行动 → 障碍与调整 → 进展 → 下一步 |
| 学习一套系统经验 | F 经验教学型 | 痛点 → 收获 → 相关经验 → 分点方法 → 行动 |
| 感受生活事件及个人反应 | G 生活叙事型 | 心情或动机 → 事件 → 反应 → 感受或发现 |

### 多个结构都合适时

- 经历只是为了证明观点，选 B；经历如何发生才是重点，选 C 或 G。
- 解决一个具体问题选 A；传授覆盖多个环节的一套经验选 F。
- 重点是后续进展选 E；重点是回顾已有结果选 C。阶段结果也可以复盘，不只按是否彻底完成判断。
- 有两个具体对象，且比较本身是主要价值，才选 D；仅有“以前和现在”不必选 D。
- 生活感受为主选 G，不强行提炼成教程。
- 仍难取舍，选最贴近原意且需补材料最少的结构。

每篇选择一个合适的主结构，不让用户自己从七种结构中选。结构用于帮助表达；原顺序已经合适时允许少改，模板不贴切时按材料的自然逻辑组织，不硬套。

选定后，参照 [结构细则](references/structures.md) 中对应的 A—G 小节，检查所需材料，再组织正文。若多个关键环节都缺材料，重新选结构，不让用户为模板硬补故事。

## 把材料放进结构

清理后仍需重新组织重点、信息顺序、开头和衔接，提高让人听下去的潜力，不只删语气词就交付。正文（或用户要求的提纲）必须落实本期具体内容：先讲哪个判断、接哪段经历、解释哪个原因、落在哪个行动或感受。不能只复述“观点—证据—解释—连接”这类标签。

写开头或调整语气、钩子、反转时，参照 [开头与表达](references/expression.md)。先定每篇的主结构或自然叙述逻辑，再优化句子；反转和钩子是可选工具，不要求全部使用，也不保证流量结果。

## 身份、系列与模板适配

沿用用户当前文档已经明确的身份、受众和表达习惯，不强制固定自称、人设或平台。相关经验有材料才写，已知上下期内容时再承接。结尾落回本期价值，可给一个自然行动建议，不堆叠多个互动要求。

在已有创作模板中使用时，读取本期定位、选题和原始口述，遵循用户指定的稿件输出位置；不把模板说明、方法库当成口述素材，不覆盖原始材料或用户自己的复述区。

实际写入以宿主提供的能力和用户授权为准。没有文档写入能力时直接返回稿件，不假装已经填入分栏，不要求调用不存在的工具，也不阻止普通聊天中的使用。用户明确只要求审阅时不擅自写入外部文档。

## 输出格式

默认直接输出：

1. **完整口播稿**：有个人语气、完整、可直接念；不混入结构分析、镜头、花字或编辑批注。
2. **结构说明**：在稿件之外用一句话说明采用的讲法和关键安排。

拆成多篇时，先用一句话说明拆分原因，再分别输出“稿件一｜主题”“稿件二｜主题”等，每篇都有完整稿和一句结构说明。主题标题仅用于区分稿件，不额外生成封面和标题策划。

“其他可用素材”仅在确有需要时附上。必要材料确实缺失时简短指出缺口，不凭空补齐。

不默认附长篇修改报告、逐项检查表、原意确认表、评分、重说提示卡或复述后的检查流程。用户要求解释改动时再解释。用户微调后尊重其表达，不反复改回模板腔。

用户明确只要结构建议或提纲时，按限定给出针对本期的结构理由、填入已有材料的具体提纲或开头示范，不只报公式；不要擅自扩写全文。

## 交付前自查（不作为默认输出）

- 每篇核心意思和个人语气是否保留，噪音是否清理？
- 是否依据主题独立性和材料决定拆篇，保留了有价值的内容？
- 结构与正文是否对应本期材料，而非泛泛套公式？
- 观点是否得到适当支撑，是否夸大因果或承诺？
- 开头提出的问题、承诺的价值，正文是否兑现？
- 是否完成用户要求的交付，而不是只解释怎么做？
